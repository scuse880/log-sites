## 1. 기본 범위

- 운영: 개인용, 계정 1개, 캐릭터 1개, 로그인 필수.
- PC: 독립 웹 게임에서 사냥·육성·강화.
- Android: 설치형 PWA에서 계획·보고서·진행도 조회.
- 분야: CS·영어·운동의 활동을 동일 캐릭터에 합산.
- 학습 기록: 게임과 독립된 원문·첨부·수정 이력 보관, 기록용 앱 단독 전환 지원.
- 직업: 초보자 → 전사 → 파이터 → 크루세이더 → 히어로.
- 콘텐츠: 기반 팩의 v83 맵·몬스터·장비·스킬 사용, 원작 명칭·ID 대응.
- 유니온: 분야별 누적 시간·숙련도 통계 화면, 전투 보너스 0.
- 제외: 다중 캐릭터·다른 직업·멀티플레이·거래·모바일 사냥·오프라인 기록.

## 2. 경험치와 능력치

- 시작: Lv.1, 리스항구, 초보자 무기, 빨간 포션 20개, 메소 0.
- 최대 레벨: 200.
- 경험치 출처: AI가 활동으로 인정한 보고서의 실제 수행 시간.
- 지급량: 1분 = 1 EXP, 소수점 버림, 세 분야 합산 하루 최대 120 EXP.
- 중복 활동 시간: 1회만 인정.
- 레벨 L의 다음 레벨 요구량: `30 + 5 × L` EXP.
- 경험치 이월: 레벨업 후 잔여량 유지, 연속 레벨업 허용.
- 경험치표: 서버·웹 클라이언트에 동일 공식 적용.
- 사냥·기존 퀘스트·이벤트·계획 완료 경험치: 0.
- 사망 경험치 감소: 0.
- 레벨업: AP 5, 1차 전직 후 SP 3; 초보자·전직 추가 지급은 기반 팩 기본값.
- AP·SP 배분: 사용자 직접 선택.
- 전투 수치: STR·DEX·INT·LUK·공격력·방어력·장비 요구조건은 기반 팩 공식 유지.
- 성장 기준: 매일 60 EXP 누적 시 Lv.10 9일 / Lv.30 51일 / Lv.70 236일 / Lv.120 655일; 4차 과제 별도.

## 3. 전직과 전투 스킬

- 전직 레벨: 1차 10 / 2차 30 / 3차 70 / 4차 120.
- 1~3차 전직: 해당 레벨 도달 후 전직 NPC 대화, 추가 시험 생략.
- 1~3차 스킬: 전직 즉시 목록 제공, 개별 해금 퀘스트 없음.
- 4차 전직: Lv.120 이상 + CS 프로젝트 1개 통과 + 전직 NPC 대화.
- 4차 과제 제출물: 실행 가능한 프로그램의 소스·실행 방법·테스트 3건의 실행 결과·핵심 로직 설명.
- 과제 통과: AI가 제출물 4항목의 충족·내용 일치를 확인한 경우 승인.
- 4차 스킬: 전직 시 일괄 해금, 현재 스킬 레벨 0, SP 투자로 습득·강화.
- 4차 초기 마스터 상한: `min(10, 원작 최대 레벨)`; 이후 원작 마스터리북 적용.
- 전투 스킬 최대 레벨·효과: 기반 팩 값 유지.

## 4. 사냥과 경제 및 수집

- 사냥 보상: 메소·장비·소비 아이템·주문서·마스터리북.
- 메소·드롭 배율: 1배.
- 드롭 목록·확률·상점 가격·장비·물약: 기반 팩 기본값.
- 주문서: 아이템별 성공률·실패 처리·강화 횟수·파괴 여부 유지.
- 강화 판정: 게임 서버 난수 처리, 일반 캐릭터 권한, 무조건 성공 설정 해제.
- 몬스터 난도·맵 접근조건: 기반 팩 값 유지, 별도 학습 잠금 없음.
- 몬스터 도감: 종류별 최초 처치 시 등록, 중복 등록·추가 경험치 없음.

## 5. 현실 능력

- CS 능력 6개: 프로그래밍 기초·메모리와 객체 수명·자료구조·디버깅·네트워크·데이터베이스.
- 영어 능력 5개: 어휘·읽기·듣기·말하기·쓰기.
- 운동 능력 3개: 동작 이해·동작 수행·훈련 기록 관리.
- 숙련도: 미측정 / 1 설명 / 2 독립 수행 / 3 변형·응용 / 4 지연 재수행.
- 4단계 조건: 3단계 평가 후 7일 이상 경과, 동급 과제 독립 재수행.
- 평가 증거: 직접 작성한 설명·코드·테스트·수행 기록.
- 증거 부족: 숙련도 유지, 인정된 활동 시간의 경험치 지급.
- 숙련도 기록: 달성한 최고 단계·평가일·근거 보존, 자동 하락 없음.
- 전투 스킬과의 개별 매핑·숙련도에 따른 스탯 직접 가산·능력 자동 생성·트리 UI: 없음.

## 6. 계획과 보고서 및 AI

- 계획 계층: 수년 → 년 → 월 → 주 → 일.
- 계획 항목: 제목·상위 목표·시작일·기한·진행/완료/보류 상태.
- 계획 수정: 상시 허용, 변경 이력 보존, 경험치 재지급 없음.
- 학습 기록: 하루 여러 건 작성·수정, 세션·주제별 고유 ID와 버전 부여.
- 일일 보고서: 활동일당 1개, 해당 기록 ID·버전·인정 시간·평가의 스냅샷 저장, 보상 확정 후 잠금.
- 원문 수정: 확정 보고서·기존 보상 유지, 수정 이력 추가, 자동 재지급 없음.
- 보고서 항목: 분야별 수행 시간·한 일·혼자 해낸 것·도움받은 부분·산출물.
- 산출물 첨부: 선택; 4차 과제 제출물은 필수.
- 날짜·일일 상한 기준: 활동일, Asia/Seoul.
- AI: [gpt-6-astra](https://developers.openai.com/api/docs/models/gpt-6-astra), `reasoning.effort=max`.
- AI 출력: 활동 인정 여부·관련 능력 ID·숙련도 판정·판정 근거·4차 과제 통과 여부.
- 경험치 보상 계산: 학습 API의 고정 규칙; 캐릭터·AP·SP·메소·아이템·강화 결과: 게임 서버 담당.
- 저장: 학습 원문·첨부 우선 저장, AI·게임 서버 상태와 무관하게 작성·조회 가능.
- 평가·보상: 일일 보고서 확정 요청 → AI 평가 → 규칙 검증 → 보상 이벤트 발행 → 게임 반영.
- 평가 실패: 보고서 보존, 같은 보고서 ID로 재시도.
- 잘못 확정된 기록: 별도 정정 이력으로 처리, 동일 보상 재지급 금지.

## 7. 학습 기록과 기록용 앱 전환

- 원본 저장: MySQL의 독립 학습 스키마, 기록 본문은 Markdown 원문 그대로 저장.
- 기록 필드: 고유 ID·사용자 ID·활동일·분야·제목·실제 수행 시간·본문·태그·생성/수정 시각.
- 학습 내용: 배운 개념·자기 설명·코드·문제 풀이·미해결 질문·다음 할 일.
- 출처: 책 제목·장·페이지·문서 URL; 관련 계획·능력 ID 연결.
- 첨부: 파일 원본은 영속 볼륨, DB에는 파일 ID·이름·형식·경로 저장.
- AI 결과: 사용자 원문과 분리, 평가 내용·근거·모델·규칙 버전·평가 시각 보존.
- 조회: 날짜·분야·태그 필터, 제목·본문 검색, 학습 시간·기록 수 통계.
- 수정·삭제: 버전 이력 유지, 삭제는 휴지통 보관, 확정 보상 변경 없음.
- 게임 연결: 독립 사용자 ID 기준 선택 연결; 캐릭터 삭제·초기화 시 학습 기록 보존.
- 실행 모드: 게임 모드 기본값; 기록 모드에서 계획·기록·검색·통계·내보내기 단독 실행.
- 기록 모드: 게임 서버 연결·게임 보상 발행 해제, AI 평가 선택, 재연결 시 자동 소급 보상 없음.
- 내보내기: ZIP에 manifest.json·전체 학습 데이터 JSON·기록별 Markdown·첨부 원본 포함.
- JSON 보존 항목: 형식 버전·고유 ID·계획·출처·태그·기록 및 수정 이력·평가·숙련도·보상 발행 이력.
- 첨부 연결: ZIP 내부 상대 경로 사용, 외부 URL 출처 별도 보존.
- 가져오기: 동일 ID·버전 중복 건너뛰기, 내용 충돌 시 별도 사본 보관, 자동 보상 없음.
- 백업: 학습 DB·첨부 원본 하루 1회 함께 백업, 최근 30회 보관.

## 8. 구현 구성

- 게임 서버: [P0nk/Cosmic](https://github.com/P0nk/Cosmic) 포크.
- PC 웹 클라이언트: [nmnsnv/maplestory-wasm](https://github.com/nmnsnv/maplestory-wasm) 포크.
- 브라우저 통신: 해당 포트의 WebSocket–TCP 프록시·리소스 서버 사용.
- 원작 리소스: 사용 권한 확보본 별도 준비, 브라우저 포트의 UI 규격 적용.
- 기록 화면: React·TypeScript PWA, 게임 실행과 독립된 기록·검색·내보내기 화면.
- 학습 API: Cosmic과 분리한 독립 Java 서비스, 자체 로그인·기록·계획·평가·통계·내보내기 담당.
- 저장소: 같은 MySQL 인스턴스의 학습용 스키마와 Cosmic 게임용 DB 분리, 학습 데이터의 게임 DB 외래 키 없음.
- 학습 테이블: users·plans·study_entries·entry_revisions·attachments·daily_reports·evaluations·skill_mastery·reward_events·game_links.
- 게임 테이블: 기존 Cosmic 데이터·몬스터 도감·보상 수신 이력.
- 계정 연결: 학습용 user_id를 기준으로 Cosmic 계정 ID·캐릭터 ID 매핑.
- 반영 경로: 학습 API의 보상 이벤트 → Cosmic 연동 모듈 → 캐릭터 변경·처리 결과 회신.
- 중복 방지: 보고서 ID별 보상 이벤트 1개, 게임 서버에서 이벤트 ID별 1회 처리·캐릭터 변경과 수신 이력 함께 저장.
- 진행도: 온라인 캐릭터 즉시 갱신, 오프라인 캐릭터 저장 후 다음 접속 시 반영.
- AI API 키: 서버에만 보관.
- 배포: 단일 호스트·Docker Compose·HTTPS, 최초 채택 커밋 고정.

## 9. 최초 구현 순서와 완료 기준

- 1단계: 브라우저 로그인·맵 이동·기본 공격·드롭 획득.
- 2단계: 독립 학습 API·PWA 기록 저장·일일 보고서·AI 평가·경험치·레벨업·AP·SP.
- 3단계: 전직·스킬·상점·주문서 강화.
- 4단계: 계획·검색·현실 능력·분야별 통계·몬스터 도감·내보내기·가져오기·백업.
- 완료: 보고서 1건으로 캐릭터 성장 반영, 재전송 시 추가 보상 0.
- 완료: 사냥 경험치 0, 메소·아이템 획득, 확률 강화 성공·실패 반영.
- 완료: 1~4차 전직 조건·SP 투자·4차 과제 및 마스터리북 동작.
- 완료: 재접속·기기 변경 후 동일 진행도 유지.
- 완료: 게임 서버·AI를 꺼도 기록 모드에서 작성·수정·검색·계획·통계 사용.
- 완료: 내보낸 ZIP을 빈 학습 DB에 가져온 뒤 원문·이력·첨부 복원, 반복 가져오기 시 중복 기록·보상 0.
