## 1. 기본 범위

- 운영: 개인용, 계정 1개, 캐릭터 1개, 로그인 필수.
- PC: 독립 웹 게임에서 사냥·육성·강화.
- Android: 설치형 PWA에서 계획·보고서·진행도 조회.
- 분야: CS·영어·운동을 초기 분야로 두되 자유롭게 추가, 여러 분야의 활동을 동일 캐릭터에 합산.
- 학습 기록: 게임과 독립된 원문·첨부·수정 이력 보관, 기록용 앱 단독 전환 지원. 독립 Java 학습 API·MySQL 학습 스키마·Markdown 원문·첨부 영속 볼륨·React PWA로 구현.
- 직업: 히어로에 한정하지 않고 기반 v83 범위의 모든 직업군을 선택할 수 있도록 설계. 직업별 전직·스킬·SP 정책을 분리하며, 서버·웹 클라이언트의 미지원 부분도 구현 범위에 포함.
- 콘텐츠: 기반 팩의 v83 맵·몬스터·장비·스킬 사용, 원작 명칭·ID 대응.
- 제외: 다중 캐릭터·멀티플레이·거래·모바일 사냥·오프라인 기록.
- 범위 해석: 기존 1캐릭터·분야 합산은 유지한다. 아래 3만 시간은 현재 이 캐릭터 1개 기준이며, 추후 분야별 캐릭터를 도입할 경우 각각 독립 적용한다.

## 2. 경험치와 능력치

- 시작: Lv.1, 빅토리아 아일랜드 내 리스항구 이외의 지역(`[제안]` 헤네시스), 초보자 무기, 빨간 포션 20개, 메소 0.
- 최대 레벨: 모든 직업 200. 원래 상한이 낮은 직업은 서버·클라이언트를 함께 확장하며, 추가 전직·신규 스킬은 자동 신설하지 않는다.
- 경험치 출처: AI가 활동으로 인정한 보고서의 실제 수행 시간. 활동 종류를 고정 목록으로 제한하지 않는다.
- 기본 지급량: 1분 = 1 EXP. 일일 획득 상한 없음.
- 최종 지급량: `floor(Σ 인정 시간(분) × 활동 계수 × 계획 배수)`. 실제 시간·인정 시간·각 배수·최종 EXP는 구분 저장.
- 계획 배수: 계획에 맞는 활동 2배, 그 외 1배. 일부만 일치하면 해당 시간만 2배 적용.
- 중복 활동 시간: 과목·계획·활동 유형이 여러 개여도 1회만 인정. 계수를 중첩하지 않으며, 구분 가능한 활동은 시간별로 나누어 계산.
- 경험치 이월: 레벨업 후 잔여량 유지, 연속 레벨업 허용.
- 사냥·기존 퀘스트·이벤트·계획 완료 버튼·추천 파일 가져오기 자체의 경험치: 0.
- 사망 경험치 감소: 0.
- 레벨업: AP 5, 1차 전직 후 SP 3. 초보자 스킬 SP는 기반 팩 기본값, 전직 추가 SP는 3절 적용. 직업별 기본 보너스와 중복 지급하지 않는다.
- AP·SP 배분: 사용자 직접 선택.
- 전투 수치: STR·DEX·INT·LUK·공격력·방어력·장비 요구조건은 기반 팩 공식 유지.

### 활동별 계수 `[제안]`

| 활동 예시 | 계수 | 인정 근거 예시 |
| --- | ---: | --- |
| 독서·강의 수강·자료 조사 | 1.0 | 읽은 범위·이해한 내용·남은 질문 |
| 배운 내용 요약·독후감·자기 말로 설명 | 1.2 | 직접 작성한 설명·요약·비교 |
| 문제 풀이·시험·기억에서 회상하기 | 1.3 | 답안·풀이 과정·오답 분석 |
| 프로그램 개발·디버깅·분석 실험·응용 프로젝트 | 1.5 | 코드 변경·재현 과정·실험 결과·설명 |
| 영어 말하기·쓰기·운동 등 직접 수행 | 1.3 | 수행 내용·시간·피드백 |
| 학습 방법 진단·메타인지 개선 실험 | 1.2 | 문제 진단·바꾼 방법·적용 기록 |
| 위에 없는 활동 | 기본 1.0 | 실제 수행 내용에 따라 기존 유형에 대응하거나 새 유형 제안 |

- 계수는 활동 이름만으로 판정하지 않고 실제 수행과 증거를 기준으로 적용한다. 실패한 구현·오답도 학습 과정이 확인되면 인정한다.
- 예: 계획에 따른 디버깅 60분은 `60 × 1.5 × 2 = 180 EXP`. 같은 60분을 요약·문제 풀이로 다시 지급하지 않는다.

### 200레벨까지의 경험치표 `[제안]`

- 누적 요구량: Lv.1 → Lv.200에 **1,800,000 EXP = 기본 환산 30,000시간**.
- 기준: [Cosmic v83 경험치 원표](https://github.com/P0nk/Cosmic/blob/97f358f047eeb94e10e22b3da0111ec7d2f2ee63/src/main/java/constants/game/ExpTable.java)의 `V(L) = exp[L]`, `L=1…199`. 이 구간 합계는 `30,950,360,817`.
- 다음 레벨 요구량: `E*(L) = 30 + 5×L + 1,694,530 × V(L) / 30,950,360,817`.
- 정수화: 각 값을 내림하고 남은 EXP를 소수부가 큰 레벨부터 1씩 추가한다. 동률은 높은 레벨 우선. 최종 합계는 정확히 1,800,000 EXP.
- 취지: 기존 초반 요구량에 옛메 표의 후반 증가분을 더한다. 원표를 단순 축소할 때 초반 레벨이 거의 즉시 오르는 문제를 피하면서 후반을 가파르게 만든다.
- 공통 표: 생성한 `config/progression/exp_table.json`과 규칙 버전을 서버·웹 클라이언트가 함께 사용.
- 3만 시간은 배수 적용 전 기준이다. 계획 2배만 계속 적용하면 실제 15,000시간, 활동 계수 1.5까지 적용하면 10,000시간에 해당한다.

| 도달 레벨 | 누적 요구 EXP | 배수 적용 전 누적 시간 |
| --- | ---: | ---: |
| 8 | 350 | 5.83시간 |
| 10 | 495 | 8.25시간 |
| 30 | 3,064 | 51.07시간 |
| 70 | 15,522 | 258.70시간 |
| 120 | 62,747 | 1,045.78시간 |
| 160 | 268,770 | 4,479.50시간 |
| 200 | 1,800,000 | 30,000시간 |

※ 위 시간은 레벨 도달 기준이며 전직 시험·4차 과제 완료 시간은 별도다.

## 3. 전직과 전투 스킬

- 전직 레벨: 모험가 기준 1차 10(마법사 8) / 2차 30 / 3차 70 / 4차 120. 다른 직업군은 원작 전직 단계·레벨을 직업별 표로 관리.
- 1~4차 전직: 전직 NPC·시험·퀘스트·필요 아이템 절차를 정상 수행하며, 시험을 생략하지 않는다.
- 전직 완료 추가 SP: **1차 1 / 2차 1 / 3차 1 / 4차 3**. 레벨업 SP와 별도, 같은 전직 완료에 1회만 지급.
- 특수 직업: 다단계 전직·직업별 SP 스킬북은 별도 정책으로 관리. 1~4차에는 위 추가 SP 규칙을 적용하고, 5차 이상의 추가 SP는 기반 팩 정책을 유지한다.
- 1~3차 스킬: 전직 즉시 목록 제공, 개별 해금 퀘스트 없음. 전직 시험과 스킬별 해금은 구분한다.
- 원작 Lv.120에 4차 전직하는 직업의 추가 조건: Lv.120 이상 + CS 프로젝트 1개 통과 + 원작 전직 시험·NPC 절차 완료.
- 4차 과제 제출물: 실행 가능한 프로그램의 소스·실행 방법·테스트 3건의 실행 결과·핵심 로직 설명.
- 과제 통과: AI가 제출물 4항목의 충족·내용 일치를 확인한 경우 승인.
- 특수 전직 체계의 대응 `[제안]`: 4차가 없거나 시점이 다른 직업은 원래 전직 구조를 유지하고, 동일 CS 프로젝트를 Lv.120의 별도 성장 과제로 기록. 레벨업 자체는 잠그지 않음.
- 4차 스킬: 해당 차수 전직 시 일괄 해금, 현재 스킬 레벨 0, SP 투자로 습득·강화.
- 4차 초기 마스터 상한: `min(10, 원작 최대 레벨)`; 이후 원작 마스터리북 적용.
- 전투 스킬 최대 레벨·효과: 기반 팩 값 유지. 특수 직업의 스킬 차수 대응은 직업별 정책으로 관리.

## 4. 사냥과 경제 및 부화기

- 사냥 보상: 메소·장비·소비 아이템·주문서·마스터리북.
- 메소·드롭 배율: 1배.
- 드롭 목록·확률·상점 가격·장비·물약: 기반 팩 기본값.
- 주문서: 아이템별 성공률·실패 처리·강화 횟수·파괴 여부 유지.
- 강화 판정: 게임 서버 난수 처리, 일반 캐릭터 권한, 무조건 성공 설정 해제.
- 몬스터 난도·맵 접근조건: 기반 팩 값 유지, 별도 학습 잠금 없음.
- 피그미의 알: **알 1개 + 부화기 1개를 소모하여 서버가 무작위 아이템 1건 지급**. 알 종류별 보상표·수량·확률을 데이터로 관리.
- 알 획득 `[제안]`: 게임 내 피그미 NPC에서 획득하며 세부 조건은 별도 조정. 부화기는 학습·시험 보상으로 획득.
- 부화기 조건: 현재 캐릭터 레벨과 해당 과목의 진도·숙련도에 맞는 문제를 직접 풀어 기준 통과. 다른 과목으로 오른 게임 레벨만으로 문제 난도를 정하지 않는다.
- 시험 경로: 사용자가 게임 밖에서 시험 생성·응시 → 문제·답안·보고서 제출 → **Astra Ultra 평가** → 규칙 검증 → 부화기 지급.
- 지급 기준 `[제안]`: 적정 난도 문제 세트·외부 시험에서 100점 환산 **90점 이상이면 부화기 1개**. 문항별 점수·난도 적합성·판정 근거 보존.
- 중복 방지: 같은 문제 세트·시험 ID의 보상은 1회. 문제 풀이 보상과 고득점 시험 보상을 중복 지급하지 않는다. 동일 답안 재제출은 추가 보상 없음.
- 보상 확정: 시험 ID·평가 버전을 미확정 일일 보고서에 연결하고 EXP와 부화기를 하나의 보상 이벤트에 포함.
- 랜덤 보상 범위 `[제안]`: v83 장비·소비 아이템·주문서·마스터리북. 직접 EXP 보상은 없음. 구체 보상표·확률은 추후 조정.
- 부화 처리: 알·부화기 소모와 보상 지급을 함께 저장, 인벤토리 부족 시 소모하지 않음. 재시도해도 재추첨·이중 지급 없음.
- 구현: 기반 팩의 피그미·부화기 처리를 실제 검증하고 부족한 보상표·추첨·소모 처리를 보완.

## 5. 현실 능력과 과목 체계

- 학습 순서: 분야·과목을 자유롭게 오가며 학습. 선형 진도 완료를 경험치의 필수 조건으로 두지 않음.
- 분류: 분야 → 과목 → 단원·주제 → 세부 개념. MySQL의 `parent_id` 계층과 기록-주제 연결 테이블로 저장.
- AI 제안: 당일 보고서에 미등록 내용이 있으면 새 과목·하위 주제·기존 과목 연결을 건의. 사용자 승인 후 등록하며 유사 과목의 중복 생성을 확인.
- 승인 전 기록은 미분류로 보관하고 활동 EXP는 정상 평가, 승인 후 과목에 연결.
- 예: Petzold의 『CODE』 전기회로 부분을 읽고 요약·독후감·문제 풀이를 제출하면 `공학 → 전기공학 → 기초 회로 → 직렬·병렬 회로` 등의 추가를 제안. 승인하면 전기공학을 과목 목록에 편입.
- 다중 분류: 하나의 기록을 CS와 전기공학 등에 연결할 수 있으나 EXP·총 수행 시간은 중복 합산하지 않음. 과목별 집계는 시간 배분값을 사용하고 합계가 실제 시간을 넘지 않게 함.
- 초기 CS 능력 6개: 프로그래밍 기초·메모리와 객체 수명·자료구조·디버깅·네트워크·데이터베이스.
- 초기 영어 능력 5개: 어휘·읽기·듣기·말하기·쓰기.
- 초기 운동 능력 3개: 동작 이해·동작 수행·훈련 기록 관리.
- 새 과목의 능력: 평가 가능한 능력·증거 기준을 AI가 제안, 사용자 승인 후 추가. 과목 생성만으로 숙련도 획득 없음.
- 숙련도: 미측정 / 1 설명 / 2 독립 수행 / 3 변형·응용 / 4 지연 재수행.
- 4단계 조건: 3단계 평가 후 7일 이상 경과, 동급 과제 독립 재수행.
- 평가 증거: 직접 작성한 설명·코드·테스트·수행 기록.
- 증거 부족: 숙련도 유지, 인정된 활동 시간의 경험치 지급.
- 숙련도 기록: 달성한 최고 단계·평가일·근거 보존, 자동 하락 없음.
- 전투 스킬과의 개별 매핑·숙련도에 따른 스탯 직접 가산·능력의 무승인 자동 생성·트리 UI: 없음. 계층은 기록 저장·검색에 사용.

### 메타인지 개선 보상 `[제안·선택 전]`

- 인정: 학습상 문제 진단 → 방법 변경 → 실제 적용 → 전후 비교 근거 확인. 속도뿐 아니라 이해도·지연 회상·오류 감소도 비교하며, 단순 다짐만으로 개선 달성 판정하지 않음.
- 활동 시간 EXP는 2절에 따라 지급. 아래는 **개선 성과에 대한 별도 보상 후보**이며 중복 적용하지 않는다.

| 보상안 | 예시 | 판단 |
| --- | --- | --- |
| 소량 EXP | 검증된 개선 사례 1건당 30 EXP, 계획 배수 미적용 | 즉각적 보상. 시간 기준 성장에 추가 EXP가 섞임 |
| 메소·아이템 | 검증된 개선 사례에 메소 또는 일반 주문서 선택 지급 | 게임에서 바로 활용 가능. 수량·경제 영향 조정 필요 |
| **칭호·기록 배지 — 권장** | ‘회상 학습 개선’ 등 개선 이력과 연결된 칭호·배지 | 성장 속도·경제를 바꾸지 않고 개선을 누적 표시, 전투 효과 없음 |

- 동일 개선·동일 비교 자료로 추가 보상을 반복 지급하지 않음. 구체 보상안은 선택 후 확정.

## 6. 계획과 보고서 및 AI

- 계획 계층: 수년 → 년 → 월 → 주 → 일.
- 계획 항목: 제목·상위 목표·시작일·기한·진행/완료/보류 상태.
- 계획 수정: 상시 허용, 변경 이력 보존, 경험치 재지급 없음.
- 계획 2배 판정 `[제안]`: 활동 시작 전에 저장된 계획의 목표·범위와 일치한 시간에 적용. 연결한 계획 ID·당시 버전·일치 근거 보존, 같은 활동에 여러 계획 배수 중첩 없음.
- 학습 기록: 하루 여러 건 작성·수정, 세션·주제별 고유 ID와 버전 부여.
- 일일 보고서: 활동일당 1개, 해당 기록 ID·버전·인정 시간·평가·시험 결과의 스냅샷 저장, 보상 확정 후 잠금.
- 원문 수정: 확정 보고서·기존 보상 유지, 수정 이력 추가, 자동 재지급 없음.
- 보고서 항목: 분야·과목별 수행 시간·한 일·혼자 해낸 것·도움받은 부분·산출물·관련 계획·문제/시험·메타인지 개선 내용.
- 산출물 첨부: 일반 활동은 선택; 4차 과제와 시험 보상 판정에 필요한 제출물은 필수.
- 날짜 기준: 활동일, Asia/Seoul.
- 일반 보고서 AI: 기존 [gpt-6-astra](https://developers.openai.com/api/docs/models/gpt-6-astra), `reasoning.effort=max`의 API 평가 경로 유지.
- 외부 시험 평가: 사용자가 Codex/Chat에서 Astra Ultra로 직접 평가받은 결과·근거를 가져오는 경로 지원. 일반 보고서 평가와 구분하여 기록.
- AI 출력: 활동 인정 여부·활동 유형·관련 능력 ID·숙련도 판정·판정 근거·계획 일치·새 과목 제안·4차 과제 통과 여부. 시험은 문항별 점수·총점·난도 적합성 추가.
- 경험치·부화기 보상 계산: 학습 API의 고정 규칙; 캐릭터·AP·SP·메소·아이템·강화 결과: 게임 서버 담당. AI가 임의 보상 수량을 확정하지 않음.
- 저장: 학습 원문·첨부 우선 저장, AI·게임 서버 상태와 무관하게 작성·조회 가능.
- 평가·보상: 일일 보고서 확정 요청 → AI 평가 및 외부 평가 결과 검증 → 규칙 검증 → 보상 이벤트 발행 → 게임 반영.
- 평가 실패: 보고서 보존, 같은 보고서 ID로 재시도.
- 잘못 확정된 기록: 별도 정정 이력으로 처리, 동일 보상 재지급 금지.

### 게임 시작 시 추천 활동: 수동 생성·파일 가져오기

- 생성: **추천 생성용 API 호출 없이**, 사용자가 Codex 또는 Chat 모드에서 직접 실행.
- 입력: 현재 레벨·과목별 진도·숙련도·미해결 질문·최근 기록·계획·가용 시간·활동 계수를 내보낸 `learning-context.json`.
- 출력: 현재 수행 가능한 추천 활동·연결 과목/계획·예상 시간·제출할 증거·추천 이유. 예상 EXP는 학습 API가 현재 규칙으로 계산하며 실제 지급은 수행 후 확정.
- 저장 규약: 아래 경로는 프로젝트 루트 기준. Windows 설치 예시는 `C:\MapleStudy\data\ai_exchange\recommendations\2026-11-02.json`.

| 경로 | 넣는 내용 |
| --- | --- |
| `data/ai_exchange/context/learning-context.json` | 앱에서 내보낸 최신 추천 생성용 맥락 |
| `data/ai_exchange/recommendations/YYYY-MM-DD.json` | Codex/Chat이 만든 추천 JSON |
| `data/ai_exchange/exams/시험ID.json` | Astra Ultra 시험 평가 결과와 원본 기록 참조 |
| `data/ai_exchange/archive/` | 가져오기 완료한 파일과 처리 결과 |

추천 JSON 최소 양식(아래 ID는 예시이며 실제 맥락 파일의 ID로 교체):

```json
{
  "schema_version": 1,
  "activity_date": "2026-11-02",
  "context_id": "ctx-example",
  "items": [{
    "id": "rec-01",
    "title": "직렬·병렬 회로를 설명하고 문제 풀기",
    "subject_ids": ["subject-example"],
    "subject_proposals": [],
    "plan_id": "plan-example",
    "activity_type": "problem_solving",
    "minutes": 30,
    "evidence": "설명과 문제 풀이 원문",
    "reason": "최근 읽은 전기회로 내용의 이해 확인"
  }]
}
```

1. 앱에서 최신 맥락 파일을 내보내 Codex/Chat에 제공한다.
2. “이 맥락과 명세의 JSON 양식에 맞춰 오늘 수행 가능한 추천 활동을 만들어줘”라고 요청한다. 과목 ID는 실제 값만 사용하고 미등록이면 `subject_ids: []`, `subject_proposals`에 과목 경로를 제안한다. 계획 미연결은 `plan_id: null`.
3. 프로젝트 폴더에 접근 가능한 Codex에는 위 경로로 저장을 요청한다. 일반 Chat에서는 JSON 파일을 내려받아 해당 폴더에 복사하거나 앱의 ‘추천 가져오기’로 업로드한다.
4. 게임 시작 시 **학습 API**가 파일의 날짜·형식·맥락 ID·계획/과목 ID를 검증하고 추천을 표시한다. 브라우저가 PC 폴더를 직접 읽는 방식은 아니다.
5. 새 파일이 없으면 마지막 추천을 생성일과 함께 표시하거나 생성 안내를 표시하며, 자동으로 API를 호출하지 않는다.

- 시험 평가 파일 필수값: 형식 버전·시험 ID·기록 ID/버전·문제/답안/채점 기준 참조·과목/진도·문항별 점수/근거·총점/만점·난도 적합성·평가 모델/설정·평가 시각.
- 가져오기만으로 EXP·아이템을 지급하지 않으며, 사용자가 연결한 일일 보고서 확정 절차에서 보상한다.

## 7. 학습 기록과 기록용 앱 전환

- 원본 저장: MySQL의 독립 학습 스키마, 기록 본문은 Markdown 원문 그대로 저장.
- 기록 필드: 고유 ID·사용자 ID·활동일·분야/과목/주제 ID·제목·실제 수행 시간·본문·태그·생성/수정 시각.
- 학습 내용: 배운 개념·자기 설명·코드·문제 풀이·미해결 질문·다음 할 일.
- 출처: 책 제목·장·페이지·문서 URL; 관련 계획·능력 ID 연결.
- 첨부: 파일 원본은 영속 볼륨, DB에는 파일 ID·이름·형식·경로 저장.
- AI 결과: 사용자 원문과 분리, 평가 내용·근거·모델·규칙 버전·평가 시각 보존. API 평가와 수동 가져오기 출처 구분.
- 조회: 날짜·분야·과목·주제·태그 필터, 제목·본문 검색, 학습 시간·기록 수 통계.
- 수정·삭제: 버전 이력 유지, 삭제는 휴지통 보관, 확정 보상 변경 없음.
- 게임 연결: 독립 사용자 ID 기준 선택 연결; 캐릭터 삭제·초기화 시 학습 기록 보존.
- 실행 모드: 게임 모드 기본값; 기록 모드에서 계획·기록·검색·통계·내보내기 단독 실행.
- 기록 모드: 게임 서버 연결·게임 보상 발행 해제, AI 평가 선택, 재연결 시 자동 소급 보상 없음.
- 내보내기: ZIP에 manifest.json·전체 학습 데이터 JSON·기록별 Markdown·첨부 원본 포함.
- JSON 보존 항목: 형식 버전·고유 ID·계획·출처·태그·과목 계층·기록 및 수정 이력·평가·숙련도·추천·시험·메타인지·보상 발행 이력.
- 첨부 연결: ZIP 내부 상대 경로 사용, 외부 URL 출처 별도 보존.
- 가져오기: 동일 ID·버전 중복 건너뛰기, 내용 충돌 시 별도 사본 보관, 자동 보상 없음.
- 백업: 학습 DB·첨부 원본 하루 1회 함께 백업, 최근 30회 보관.

## 8. 구현 구성과 필요한 프로그램

- 게임 서버: [P0nk/Cosmic](https://github.com/P0nk/Cosmic) 포크.
- PC 웹 클라이언트: [nmnsnv/maplestory-wasm](https://github.com/nmnsnv/maplestory-wasm) 포크.
- 브라우저 통신: 해당 포트의 WebSocket–TCP 프록시·리소스 서버 사용.
- 원작 리소스: 사용 권한 확보본 별도 준비, 브라우저 포트의 UI 규격 적용. 현재 포트 문서 기준 v83 리소스와 v153+ `UI.wz`를 NX로 변환.
- 기록 화면: React·TypeScript PWA, 게임 실행과 독립된 기록·검색·내보내기 화면.
- 학습 API: Cosmic과 분리한 독립 Java 서비스, 자체 로그인·기록·계획·평가·통계·내보내기·추천/시험 파일 가져오기 담당.
- 저장소: 같은 MySQL 인스턴스의 학습용 스키마와 Cosmic 게임용 DB 분리, 학습 데이터의 게임 DB 외래 키 없음.
- 학습 테이블: users·plans·study_entries·entry_revisions·attachments·daily_reports·evaluations·skill_mastery·reward_events·game_links. subjects·topics·entry_topics·subject_proposals·recommendations·exams·metacognition_reviews 추가.
- 게임 테이블: 기존 Cosmic 데이터·보상 수신 이력·피그미 보상표/부화 이력.
- 계정 연결: 학습용 user_id를 기준으로 Cosmic 계정 ID·캐릭터 ID 매핑.
- 반영 경로: 학습 API의 보상 이벤트 → Cosmic 연동 모듈 → 캐릭터 변경·처리 결과 회신.
- 중복 방지: 보고서 ID별 보상 이벤트 1개, 게임 서버에서 이벤트 ID별 1회 처리·캐릭터 변경과 수신 이력 함께 저장. 시험 ID별 부화기 보상도 중복 방지.
- 진행도: 온라인 캐릭터 즉시 갱신, 오프라인 캐릭터 저장 후 다음 접속 시 반영.
- AI API 키: 서버에만 보관. 수동 추천 생성에는 API 키를 사용하지 않음.
- 배포: 단일 호스트·Docker Compose·HTTPS, 최초 채택 커밋·의존성 버전 고정. 학습 DB·첨부·파일 교환 폴더는 영속 보관.

| IDE·DB 관리 도구(선택) | IntelliJ IDEA/VS Code로 개발, HeidiSQL/DBeaver로 DB 확인 |

## 9. 최초 구현 순서와 완료 기준

- 1단계: 브라우저 로그인·빅토리아 시작·맵 이동·기본 공격·드롭 획득, 전체 직업군 호환성 점검.
- 2단계: 독립 학습 API·PWA 기록 저장·일일 보고서·AI 평가·활동 계수·계획 2배·공통 경험치표·레벨업·AP·SP.
- 3단계: 직업별 전직·시험·스킬·상점·주문서 강화·외부 시험 평가 가져오기·피그미 알/부화기.
- 4단계: 계획·검색·현실 능력·새 과목 제안·과목별 통계·수동 추천 가져오기·선택한 메타인지 보상·내보내기·가져오기·백업.
- 완료: 보고서 1건으로 캐릭터 성장·시험 보상 반영, 재전송 시 추가 보상 0.
- 완료: 일일 획득 상한 없이 실제 활동·계수·계획 배수대로 지급, 분야 중복 분류로 시간/EXP 증가 없음.
- 완료: Lv.1→200 요구량 합계 1,800,000 EXP, 서버·웹 표 일치, 모든 직업의 200레벨 성장 가능.
- 완료: 사냥 경험치 0, 메소·아이템 획득, 확률 강화 성공·실패 반영.
- 완료: 직업별 전직 시험·추가 SP 1/1/1/3·SP 투자·4차 과제 및 마스터리북 동작, 특수 직업 대응 확인.
- 완료: 적정 난도 고득점 시험으로 부화기 지급, 알/부화기 소모·랜덤 보상·재시도 중복 방지 동작.
- 완료: 추천 생성 API 호출 없이 지정 폴더/업로드의 추천 파일을 게임 시작 화면에 표시.
- 완료: 자유 순서 학습 기록이 과목·계층별로 누적되고, 사용자 승인한 신규 과목에 연결됨.
- 완료: 재접속·기기 변경 후 동일 진행도 유지.
- 완료: 게임 서버·AI를 꺼도 기록 모드에서 작성·수정·검색·계획·통계 사용.
- 완료: 내보낸 ZIP을 빈 학습 DB에 가져온 뒤 원문·이력·첨부 복원, 반복 가져오기 시 중복 기록·보상 0.
